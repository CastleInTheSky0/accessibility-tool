# 平板端专用布局

## Goal

为 768×1024 竖屏和 1024×768 横屏设计并实现区别于手机和桌面的平板专用布局，充分利用中等宽度、横竖屏和触摸输入条件。

## Mandatory Design-first Scope

第一阶段只允许产出：

- 768×1024 竖屏、1024×768 横屏线框图／高保真稿
- 页面结构、工具栏默认／展开／收起／固定状态
- 功能按钮、设置、弹窗、连续朗读、大字幕和音色入口
- 平板与手机差异、横屏与竖屏差异、建议断点
- 触摸目标、安全区域、软键盘、滚动、长文本、深色／高对比、键盘／读屏流程

设计必须经历：设计 → 用户确认 → 调整 → 再次确认 → 实现。

## Non-goals Before Confirmation

- 修改 `src/`、运行时 CSS、正式 `public/` 结构、工具栏交互、公共 API 或构建产物。
- 直接放大手机布局或缩小桌面单行工具栏作为平板方案。

## Technical Approach

- 在移动布局规则稳定后定义平板独立断点和横竖屏状态矩阵。
- 共享业务控制器，只调整已确认的呈现、导航和空间分配。
- 明确 1024×768 平板横屏与现有桌面 1024px 契约的输入模式／视口判定冲突。

## Acceptance Criteria

- [ ] 两个规定平板尺寸均有完整设计。
- [ ] 平板与手机、横屏与竖屏差异明确。
- [ ] 所有新功能入口、浮层和字幕布局有完整状态。
- [ ] 触摸、键盘、读屏、safe-area、软键盘和长文本规则明确。
- [ ] 用户完成两次明确设计确认后才出现生产实现改动。
- [ ] 实现后横竖屏切换不丢状态、不困住焦点、不遮挡内容。

## Definition of Done

- 设计确认、实现、自动化和真实平板人工测试完整。
- 手机和桌面布局不回归。

## Unit Test Plan

- 断点／方向状态、布局选择、焦点与展开状态保持。

## E2E Test Plan

- 768×1024、1024×768 的触摸、键盘、旋转、长文本、字幕和设置浮层。
- axe、forced-colors、reduced-motion 和 200% 缩放。

## Documentation Update Plan

- 新增平板设计说明／响应式规则，更新 README、兼容性和人工测试。
