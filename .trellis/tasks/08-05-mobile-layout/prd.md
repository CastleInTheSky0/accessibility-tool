# 移动端专用布局

## Goal

为 360×800 和 390×844 手机视口设计并实现适合触摸、窄屏、安全区域和软键盘环境的专用工具栏与功能面板，同时保持桌面行为和公共 API 兼容。

## Mandatory Design-first Scope

第一阶段只允许产出：

- 页面设计说明
- 360×800、390×844 线框图／高保真稿
- 工具栏展开、收起、固定和功能按钮排列
- 设置面板、弹窗／浮层、连续朗读控制、大字幕和音色入口
- 触摸目标、安全区域、刘海屏、软键盘、滚动、长文本和小屏规则
- 深色、高对比、现有配色、键盘和屏幕阅读器流程
- 手机与桌面差异、建议断点和横竖屏行为

设计必须经历：设计 → 用户确认 → 调整 → 再次确认 → 实现。

## Non-goals Before Confirmation

- 修改 `src/` 响应式实现、运行时 CSS、正式工具栏布局和交互。
- 修改 `public/` 正式页面结构、公共 API 或构建产物。
- 以整体缩放或横向滚动代替手机专用布局。

## Technical Approach

- 设计阶段先建立布局状态、触摸和可访问性交互矩阵。
- 生产实现阶段才把已确认断点、safe-area 和软键盘规则写入 Shadow DOM UI／SCSS。
- 复用前四项功能的稳定控制器，不在布局任务复制业务状态。

## Acceptance Criteria

- [ ] 两个规定手机尺寸均有完整设计。
- [ ] 覆盖默认／展开／收起／固定、设置、浮层、连续朗读、字幕和音色入口。
- [ ] 触摸目标、safe-area、刘海、软键盘、滚动和长文本规则明确。
- [ ] 深色、强制配色、键盘和读屏流程明确。
- [ ] 用户完成两次明确设计确认后才出现生产实现改动。
- [ ] 实现后两个尺寸无功能丢失、不可达控制或非预期横向滚动。

## Definition of Done

- 设计确认记录、实现、自动化和真实设备人工测试完整。
- 桌面端和公共 API 不回归。

## Unit Test Plan

- 响应式状态选择、展开／收起、焦点转移、safe-area 计算和软键盘状态。

## E2E Test Plan

- 360×800、390×844 的触摸、键盘、旋转、缩放、长文本和大字幕。
- axe、forced-colors、reduced-motion 和焦点可见性。

## Documentation Update Plan

- 新增移动设计说明／响应式规则，更新 README、兼容性、键盘和人工测试。
