# 大字幕

## Goal

同步展示当前有效朗读文本，为听力、认知和环境受限用户提供清晰、高对比、可关闭且不会造成屏幕阅读器双重播报的视觉字幕。

## Scope

- 字幕显示、关闭和重新打开入口。
- 与 `speechstart`、`speechend`、取消和错误同步。
- 连续朗读中按当前有效段落更新。
- 明确字号、行高、高对比、长文本换行／滚动以及简繁体与拼音显示。
- 完整键盘操作和屏幕阅读器语义。
- 字幕固定在页面底部，不提供位置调整。
- `close()`、`destroy()` 和过期语音请求时清理。
- 定义桌面、手机和平板的展示差异，但移动／平板生产布局仍受各自设计门禁控制。

## Non-goals

- 字幕自身触发语音、使用 `aria-live` 重复朗读当前文本。
- 语音识别、自动翻译、逐词时间轴或视频字幕文件。
- 在移动／平板设计确认前实现其正式响应式布局。

## Technical Approach

- 字幕只订阅现有有效语音请求／连续阅读状态，不建立第二套播放状态。
- 使用内部当前朗读文本提供者传递正文；公共 `speechstart` 继续只暴露 `textLength`，不把页面正文加入公共事件 payload。
- 当前文本容器默认不使用会重复播报的 live region；控制状态另用简短可访问名称反馈。
- 使用 Shadow DOM 内独立可清理的 overlay，与阅读高亮和区域焦点所有权分离。
- 长文本采用有界高度、自然换行和用户可控滚动。
- 简繁转换与拼音生成仅处理当前运行时字幕文本，不修改朗读原文，也不写入存储、事件、日志或网络请求。
- 浏览器版 `opencc-js` 与 `pinyin-pro` 通过静态导入参与正式构建，并随工具代码一同压缩进主 IIFE 产物 `accessibility-tool.min.js`；宿主网站始终只需引用这一个 JS 文件。
- 不使用 CDN、动态 `import()`、额外语言包 JS 或运行时字典下载；简繁与拼音转换在浏览器本地完成，运行时零网络请求。
- 当前朗读原文快照是唯一数据源：简体、繁体和拼音均从原文独立生成，切换显示模式时不在既有转换结果上反复转换。
- 简繁转换采用标准简体／标准繁体规则，不默认引入台湾或香港地区词汇转换；转换或拼音生成失败时保留原文，不中断字幕及朗读流程。
- 按依赖探测结果，正式主包预算约为原始 `2.8 MB`、gzip `750 KB`；最终数值以生产构建统计为准并记录在任务验收结果中。

## What I Already Know

- 连续朗读已经完成并归档，`ReadingController#getCurrentSegment()` 可提供当前有效段落，工具层目前只把段落索引、总数和文本长度传给连续朗读控制面板。
- `SpeechController` 以递增 `requestId` 忽略过期 start/end/error 回调，大字幕应复用同一有效请求边界。
- 顶部工具栏固定高度为 `146px`，桌面版心最大宽度为 `1280px`；字幕固定贴在视口底部，不需要与顶部工具栏联动。
- 大字幕不能使用正文 `aria-live`，否则会与浏览器语音形成重复播报。
- 现有 `PreferenceStore` 已保存功能开关与视觉／语音偏好；字幕可复用同一存储，但只能保存启用状态、字号、简／繁体模式和拼音显示开关，禁止保存当前或历史字幕正文。
- 五个受保护用户文件继续不纳入本任务修改或提交范围。

## Evolving Requirements

- 桌面字幕是独立视觉浮层，不改变宿主页面布局。
- 主工具栏新增独立“`大字幕`”开关，排列在“`大界面`”与“`固定`”之间；桌面工具栏从 15 个增至 16 个控件，但 `1280px` 版心和单行布局保持不变。
- “读屏专用”工具栏也保留“`大字幕`”入口，排列在“`连续朗读`”之后；两个入口共享同一启用状态和 `aria-pressed` 值。
- 字幕以全宽条形固定在视口底部并紧贴底边，不提供顶部／底部切换、自由拖动、任意缩放或坐标位置保存。
- 字幕提供 `28px`、`36px`、`48px` 三档字号，默认 `36px`；字号切换必须使用可聚焦控件并暴露当前值。
- 桌面字幕宽度始终铺满当前视口，不设置最大宽度或左右安全边距；正文最大高度约为 `32vh`，超出时只在正文区域纵向滚动。
- 字幕启用状态、字号、简／繁体模式和拼音显示开关通过现有偏好存储跨页面保留；存储只包含枚举或布尔设置，永不包含字幕正文。
- “重置”把字幕恢复为关闭、`36px`、简体和拼音关闭；关闭工具只清理当前字幕文本和计时器，不删除用户保存的字幕偏好。
- 字幕前景、背景、边框和焦点样式跟随工具当前五种配色方案；`forced-colors: active` 时改用系统颜色并保留清晰边界与焦点指示。
- 字幕覆盖所有通过统一 `SpeechController` 真正开始播放的语音：页面单次朗读、连续朗读、音色试听和工具语音提示。
- 只有有效请求触发实际 `onStart` 后才显示文本；尚未开始、已取消、已过期或适配器拒绝播放的请求不得提前显示。
- 自定义 `SpeechAdapter` 与浏览器本地语音遵循同一字幕边界；大字幕不根据来源建立例外分支。
- 用户在语音已经播放时开启字幕，立即补显当前有效请求文本；连续朗读暂停时开启字幕，补显当前段落并显示非 live 的“已暂停”视觉状态。
- 补显只能读取当前 generation／request token 对应的运行时快照；已结束且进入 `3s` 保留期的文本可继续补显，已取消、错误或生命周期失效的文本不可恢复。
- 字幕浮层始终显示紧凑控制区，提供简体／繁体切换、拼音显示开关、`28/36/48px` 字号选择和关闭字幕；控制区不因无操作自动隐藏。
- 简体／繁体为互斥选择，默认简体；切换只改变字幕的视觉文字，不改变语音合成输入、当前请求 token 或公共事件。
- 拼音为独立开关，默认关闭；开启时在汉字字幕上方逐段显示带声调拼音，简体和繁体共用同一发音结果，不逐字机械加空格导致标点错位。
- 简繁转换使用浏览器版 `opencc-js`，拼音使用 `pinyin-pro`；两项依赖均内联进主构建产物，接入方不需要再引用语言包、样式文件或第三方脚本。
- `opencc-js` 使用标准简体／标准繁体双向转换配置，不默认执行台湾／香港地区用词转换；拼音允许依赖库进行有限上下文判音，但不承诺所有多音字在任意网页语境下完全准确。
- 遇到非中文、数字、英文、符号或无法可靠转换的内容时保留原内容；转换失败时回退显示原始字幕，不影响朗读和连续会话。
- 所有控制均使用原生可聚焦按钮或单选语义，支持 Tab／Shift+Tab、Enter／Space，并有稳定的可访问名称、当前状态和焦点样式。
- 字幕正文与控制区分离；正文滚动不会移动或遮挡控制，控制区在最大高度下仍保持可见。
- 字幕“启用”与浮层“可见”分离：启用但没有 playing、paused 或 retained 文本时，浮层完全隐藏且不占页面空间；下一条有效语音开始时自动出现。
- 空闲状态不显示“等待朗读”占位，也不保留过期正文；工具栏开关继续以 `aria-pressed` 表示字幕启用偏好。
- 每个新的有效语音请求或连续朗读新段落显示时，字幕正文滚动位置重置为顶部；字号、简繁体或拼音显示变化不重置正文滚动。
- 自动显示、文本替换和滚动重置绝不调用 `focus()`，不抢夺页面、工具栏或字幕控制区中的当前键盘焦点。
- 用户从字幕浮层控制区关闭字幕后，优先把焦点返回当前可见且可操作的工具栏“`大字幕`”按钮；若按钮不可用，则恢复进入字幕控制区前记录的页面深层焦点，最后才回退到页面主体。
- 自动隐藏、朗读结束、取消、错误、路由变化、`close()` 或 `destroy()` 不主动移动焦点；只有用户在即将被移除的字幕控制区内显式关闭时执行焦点恢复。
- 本期不注册大字幕全局快捷键，也不扩展可配置快捷键 API；开启、关闭、字号、简繁体和拼音显示均通过工具栏或字幕浮层控件完成。
- 公共配置在 `features` 中增加大字幕功能开关，公开状态与 `statechange` 增加 `captionEnabled`、`captionFontSize`、`captionScript` 和 `captionPinyinEnabled`；不再增加 `captionPosition`，也不新增大字幕专用方法。
- 公共事件不得包含字幕正文、当前语音来源、Element 或内部 request token；`speechstart` 继续只暴露 `textLength`。
- 浏览器或自定义适配器不支持语音合成时，大字幕入口仍可开启，并进入纯文字回退模式：页面原本要朗读的对应文本只显示在字幕浮层中，不尝试播放音频。
- 纯文字回退不得伪造公共 `speechstart`／`speechend`，也不得报告语音播放成功；视觉状态标签使用“`显示中`”而不是“`朗读中`”。
- 纯文字连续模式根据文本长度与当前语速估算每段展示时间，单段下限约 `3s`、上限约 `15s`；计时结束后沿既有连续朗读序列推进下一有效段落。
- 纯文字连续模式保留暂停、继续和停止；暂停冻结剩余展示时间，继续从剩余时间恢复，不从头重新计时，语速变化从下一段开始生效。
- 旧 generation 的推进计时器必须在停止、取消、路由、dialog、reset、close、destroy 或新会话开始时失效，不能推进新会话。
- 纯文字单次模式复用现有页面朗读内容选择和触发规则：键盘焦点、指针悬停／点击、区域导航、tabs 及其他原本会进入统一朗读入口的工具语音提示都显示对应文字。
- 纯文字回退不放宽 `ignoreSelectors`、`aria-hidden`、`inert`、隐私输入、不可见节点、Shadow DOM／iframe 和重复目标抑制规则；内容资格与正常朗读保持一致。
- 纯文字单次字幕也按文本长度与当前语速估算 `3–15s` 的“显示中”阶段，随后进入约 `3s` 的“已结束”保留阶段再隐藏。
- 新的有效单次目标在任一计时阶段到来时立即替换正文、滚动回顶部并重新计时；旧目标计时器不得清理或覆盖新目标。
- 语音请求在有效 `onStart` 前同步抛错、返回不可启动或触发 `onError` 时，仍按现有公共契约发出一次 `error`，随后自动把该请求切换为纯文字显示。
- 启动失败后的单次内容按纯文字时长规则完成；连续内容不终止会话，当前段按纯文字计时推进，后续段仍可重新尝试语音并在各段独立失败时回退。
- 语音已经有效开始后中途报错时，发出一次 `error`，保留当前正文并把状态从“朗读中”切为“显示中”；以该段估算总时长扣除已播放经过时间后继续，剩余时长仍夹在可读的最小边界内。
- 中途报错不补发 `speechend`；连续模式在剩余文字时长结束后推进下一段，下一段重新尝试语音。
- 回退过程不得补发虚假的 `speechstart`／`speechend`，也不得为同一次失败重复发出 `error`。
- 用户关闭大字幕时，正常音频请求继续播放，音频支持下的连续朗读也继续；字幕只清理视觉文本和相关保留计时。
- 若当前会话是完全无音频的纯文字连续模式，关闭大字幕同时以显式停止语义结束连续会话，避免后台无声推进；纯文字单次内容则直接取消显示计时并清理。
- “朗读”总开关只控制音频输出，不控制大字幕偏好。关闭朗读时立即取消当前音频，但若大字幕仍开启，后续单次触发继续以纯文字方式显示。
- 连续会话进行中关闭朗读且大字幕开启时，不停止会话；当前段切换为纯文字剩余时长并继续后续序列。再次开启朗读后，从下一段开始恢复尝试音频，不中途重启当前段。
- 当朗读和大字幕都关闭时，页面触发不产生任何音频或文字输出，连续会话按现有 disabled 语义停止。
- 大字幕开启而朗读关闭时，工具自身原本会进入统一语音提示入口的操作反馈仍以纯文字字幕显示，例如固定、配色、字号和模式切换提示；不尝试播放音频。
- 工具提示与页面正文使用同一 token、替换、滚动和时长规则；提示本身不得触发新的字幕设置反馈循环。
- 调整字幕字号、简繁体或拼音显示时，只通过按钮选中状态和现有简短状态区域反馈“字幕字号 28/36/48px”“字幕已切换为简体／繁体”“字幕拼音已开启／关闭”；不得替换当前原始文本快照或创建新的字幕输出请求。
- 无语音能力时，字幕仍遵守同一正文隐私、字号、简繁体、拼音、配色、焦点、清理和持久化规则。
- 字幕正文使用普通、可聚焦的滚动区域，提供稳定的可访问名称以便屏幕阅读器按需浏览；不得设置 `aria-live`、`role="status"`、`role="alert"` 或其他自动播报语义。
- 文本更新不通过工具栏现有 live region 宣告全文；仅用户操作字号、简繁体、拼音或关闭时，可使用简短且不包含正文的状态反馈。
- 进入或退出工具“`大界面`”／浏览器原生全屏时，保持字幕启用状态、当前正文、字号、简繁体、拼音开关和滚动位置；字幕继续铺满新视口，只重新计算最大高度。
- 全屏切换不移动焦点、不重启语音、不延长或重置 `3s` 保留计时；若全屏 API 失败，字幕状态保持原样。
- 字幕浮层显示非 live 的紧凑视觉状态标签：有效播放时“`朗读中`”、连续朗读暂停时“`已暂停`”、正常结束后的约 `3s` 保留期内“`已结束`”。
- 状态标签不得获得自动焦点或通过 live region 宣告；取消、错误和生命周期清理会直接隐藏浮层，不显示残留的“已取消／错误”正文状态。
- 字幕正文只在工具内部流转，不进入公共事件、日志、存储或网络请求。
- 字幕必须随当前有效语音请求更新，旧请求不能覆盖新内容。
- 单次朗读正常结束后保留当前字幕约 `3s` 再隐藏；新朗读在计时期间开始时，必须取消旧隐藏计时并立即显示新文本。
- 连续朗读的相邻段落直接替换，不在段落间清空或闪烁；暂停时无限期保留当前段落，继续时从重播段落同步更新。
- 显式停止、取消、错误、路由变化、`close()`、`destroy()` 和重置立即清空字幕并取消待执行的隐藏计时。
- 缩放和窄化时自然换行，只允许内容区域纵向滚动，不产生横向滚动。

## Decision (ADR-lite)

### 字幕位置

**Context**：位置切换增加控制密度和持久化状态，用户希望大字幕保持稳定、直接贴在页面底部。

**Decision**：大字幕固定为全宽底部条形并紧贴视口底边，不提供位置按钮，也不保存位置状态。

**Consequences**：交互更精简且位置可预测；页面底部内容可能被暂时遮挡，用户可关闭字幕释放空间。

### 朗读结束后的保留策略

**Context**：立即隐藏会在连续朗读的相邻段落间产生闪烁；永久保留又容易让用户误认为语音仍在进行。

**Decision**：正常单次朗读结束后保留约 `3s`；连续朗读无缝替换下一段；暂停时保留；停止、取消、错误和工具生命周期清理时立即清空。

**Consequences**：字幕在自然结束时有短暂复看窗口，又能在中断和失效时保持状态准确。实现必须以 generation／request token 保护隐藏计时，禁止旧计时清除新字幕。

### 主工具栏入口

**Context**：大字幕同时服务单次与连续朗读，需要始终可发现的独立入口；但用户希望它在视觉展示功能附近，而不是插入开头的语音功能组。

**Decision**：新增独立“`大字幕`”开关，顺序为“`大界面 → 大字幕 → 固定`”。保留既有“`语速 → 音色 → 配色`”顺序，工具栏总数增至 16 个控件。

**Consequences**：字幕入口语义直接且位置符合屏幕展示能力分组；实现必须在不超过 `1280px` 的条件下验证 16 控件单行、文字可读和焦点轮廓完整。

### 字幕尺寸

**Context**：固定字号无法同时满足一般阅读与低视力用户；无限连续缩放会增加控件和状态复杂度。

**Decision**：提供 `28px`、`36px`、`48px` 三档，默认 `36px`；字幕使用 `100%` 视口宽度且不设置最大宽度，正文最大高度约 `32vh`，自然换行并仅允许纵向滚动。

**Consequences**：三档设置易于键盘操作和自动化验证；`200%` 缩放与窄视口下仍需保证全宽条形不产生横向滚动，且控制区保持可达。

### 设置持久化

**Context**：字号、简繁体与拼音显示属于稳定的无障碍偏好；若每次打开都恢复默认，用户需要重复配置。字幕正文则属于页面内容，不能进入持久化存储。

**Decision**：跨页面保存启用状态、`28/36/48px` 字号、简／繁体模式和拼音显示开关。重置恢复为关闭、`36px`、简体、拼音关闭；关闭／销毁只清除运行时正文。

**Consequences**：用户设置可持续复用，且隐私边界清晰；旧版本存储缺少字幕字段时必须安全采用默认值。

### 字幕配色

**Context**：固定黑底白字稳定但会与用户主动选择的高对比方案冲突；独立字幕配色会重复现有设置并增加状态复杂度。

**Decision**：字幕跟随工具当前的原始、白底黑字、黑底黄字、黄底黑字和蓝底白字方案；系统强制配色时使用 `Canvas`、`CanvasText`、`ButtonText`、`Highlight` 等系统色。

**Consequences**：字幕与工具整体视觉偏好一致，不新增持久化字段；必须逐一验证五种配色、深色主题和强制配色下的正文、控制区、滚动条与焦点可辨性。

### 字幕内容范围

**Context**：只显示页面正文会让音色试听和工具语音出现“听得到但看不到”的不一致；直接监听公共事件又无法安全取得正文。

**Decision**：所有经统一 `SpeechController` 实际开始播放的语音均进入字幕。正文通过内部有效请求快照传递，公共 `speechstart` payload 继续只提供 `textLength`。

**Consequences**：字幕和实际音频保持一一对应，也自然兼容自定义适配器；实现需要让语音控制器提供只在工具内部可见的当前请求快照，并在 cancel/error/end/lifecycle 时可靠失效。

### 中途开启与暂停补显

**Context**：等待下一条语音才显示会让用户开启字幕后短时间无反馈；暂停状态已有明确的当前连续朗读段落。

**Decision**：开启字幕时立即显示正在播放的有效请求；若连续朗读处于暂停，则显示当前段落并标记“已暂停”。正常结束后的 `3s` 保留窗口内也允许补显。

**Consequences**：字幕开关即时生效；运行时必须区分 playing、paused、retained、cancelled/error/expired，且只保留内存中的单条当前文本快照。

### 浮层控制区

**Context**：自动隐藏控制区可减少视觉占用，但会降低键盘、触摸和认知用户对简繁体、拼音、字号和关闭能力的发现性。

**Decision**：始终显示紧凑控制区，提供简体／繁体、拼音、三档字号和关闭；不采用悬停出现或超时隐藏。

**Consequences**：操作入口稳定且无需额外显隐状态；设计需要压缩控制区高度，并保证正文滚动时控制区固定可见。

### 空闲状态

**Context**：持续显示空字幕会遮挡页面并让用户误以为语音仍在等待；保留过期文本又会产生状态歧义。

**Decision**：大字幕偏好保持开启，但无有效文本时整个浮层隐藏；有新语音时自动出现，不显示空闲占位。

**Consequences**：页面空闲时无额外遮挡；设置只能通过工具栏入口修改，浮层内控制在有字幕内容时可用。

### 新内容与滚动位置

**Context**：保留旧滚动位置可能让新段落从中部开始而看不到开头；暂缓更新则会让视觉字幕与音频不同步。

**Decision**：每条新语音显示时把正文滚动归零，但不改变任何键盘焦点。字号、简繁体和拼音切换不主动重置滚动。

**Consequences**：用户总能从新字幕开头阅读，且不会发生焦点抢占；实现和测试需将 `scrollTop` 更新与焦点状态分开验证。

### 关闭字幕后的焦点

**Context**：关闭按钮位于即将隐藏的浮层内，若不处理焦点，浏览器可能把焦点落到不可预测的位置。

**Decision**：用户显式关闭时优先返回可见的工具栏“大字幕”按钮；否则恢复此前页面焦点，最终回退至页面主体。非用户触发的自动隐藏不移动焦点。

**Consequences**：键盘用户拥有稳定返回点；实现需复用 open Shadow Root／同源 iframe 的深层焦点解析能力，并避免在生命周期清理时错误抢焦点。

### 快捷键范围

**Context**：全局组合键可以提高速度，但容易与网页、浏览器、操作系统和辅助技术既有快捷键冲突；可配置快捷键会扩大公共 API。

**Decision**：大字幕本期不增加全局快捷键，只提供工具栏和浮层内的显式控件。

**Consequences**：避免新的键盘冲突和配置迁移；未来若统一设计快捷键系统，可在独立任务中增加。

### 读屏专用模式入口

**Context**：大字幕同时服务听力、低视力和认知用户；进入读屏专用模式后移除入口会让同一偏好不可访问。

**Decision**：读屏专用工具栏继续显示“大字幕”，位置在“连续朗读”之后；主、读屏两个入口同步状态。

**Consequences**：模式切换不会丢失字幕控制能力；实现需覆盖两个入口的状态同步、键盘顺序和焦点返回回退。

### 屏幕阅读器语义

**Context**：完全隐藏正文会阻止用户主动检查内容；live region 自动播报则会与正在播放的语音形成重复输出。

**Decision**：正文作为普通可聚焦滚动区域暴露给辅助技术，但不使用任何 live／alert 语义。更新本身保持静默。

**Consequences**：屏幕阅读器用户可按需进入并阅读，同时不会被强制重复播报；自动化测试需断言无 live 祖先、无全文状态公告和稳定的键盘访问。

### 全屏与大界面

**Context**：全屏切换只是视口和呈现容器变化，不代表语音请求失效；隐藏或恢复默认设置会打断用户阅读。

**Decision**：保持当前字幕及全部偏好，仅重算底部全宽条形的高度约束；不改变焦点、语音或保留计时。

**Consequences**：字幕在模式切换前后连续可读；实现需响应 `fullscreenchange` 和视口尺寸变化，并保持紧贴底边且无横向滚动。

### 简繁体与拼音显示

**Context**：不同中文读者可能更熟悉简体或繁体，识字学习和认知辅助场景也需要在不改变朗读音频的前提下查看拼音。

**Decision**：控制区提供互斥的“简体／繁体”按钮和独立“拼音”开关。转换基于内存中的当前原文生成视觉派生文本；拼音显示在汉字字幕上方，带声调并保持标点与非中文内容可读。

**Consequences**：同一字幕可服务更多阅读需求；实现需选择可本地运行、可打包且无需网络的确定性转换方案，并测试常用异体字、繁简歧义、数字英文混排、多音字回退和长文本性能。

### 单文件语言能力交付

**Context**：大字幕需要简繁转换和拼音能力，但工具提供给第三方网站时应继续保持只引用一个 JS 文件的接入方式，不能要求宿主额外管理 CDN、字典或语言包版本。

**Decision**：将浏览器版 `opencc-js` 和 `pinyin-pro` 作为构建依赖静态导入，并全部打进 `accessibility-tool.min.js`。不使用动态加载、CDN、额外语言包 JS 或运行时网络请求；简繁采用标准简体／标准繁体规则。

**Consequences**：第三方接入方式保持为单个 `<script>`，离线和受限网络环境也可使用全部字幕能力；主包预计增加到原始约 `2.8 MB`、gzip 约 `750 KB`，需在正式构建中核验体积、初始化耗时和首次转换性能。

### 播放状态标签

**Context**：短暂保留已结束文本便于复看，但若没有状态标识，用户可能误认为语音仍在播放。

**Decision**：显示“朗读中／已暂停／已结束”三种紧凑视觉标签，全部保持静默；错误和取消直接清空。

**Consequences**：保留文本的含义更清楚，且不会增加读屏重复输出；测试需覆盖状态与生命周期精确同步。

### 公共 API 边界

**Context**：宿主页面需要配置功能可用性并观察用户偏好，但不需要取得页面朗读正文；新增专用命令会重复现有统一状态模式。

**Decision**：只扩展 `FeatureId`、`AccessibilityToolState`、`PersistedPreferences` 和统一 `statechange`；不新增专用方法或字幕正文事件。

**Consequences**：保持 v0.1 API 风格和链式接口稳定，同时避免正文泄露；文档需明确新增状态字段及旧存储默认回退。

### 无语音能力的纯文字回退

**Context**：禁用或隐藏大字幕会让不支持语音合成的浏览器完全失去对应文字展示能力；但没有实际音频时不能沿用语音成功事件和“朗读中”文案。

**Decision**：大字幕保持可用，原本要朗读的文本可改为纯文字显示；不发出虚假语音事件，视觉状态明确标记为“显示中”。

**Consequences**：大字幕可独立提供视觉文本辅助；实现需在内部区分 audio-backed 与 text-only 请求，并为连续内容维护独立但共享会话 generation 的展示计时器。

### 纯文字连续推进

**Context**：没有音频 `end` 回调时，连续序列需要可预测的段落结束边界；只允许手动切换会显著降低连续模式价值。

**Decision**：按文本长度和当前语速估算展示时间，夹在约 `3s–15s` 之间；暂停冻结剩余时间，继续恢复，下一段再采用最新语速。

**Consequences**：无语音浏览器仍可获得自动连续字幕；测试必须使用可控时钟覆盖上下限、暂停剩余时间、语速变更和过期计时器。

### 纯文字单次触发

**Context**：若纯文字模式另建一套触发规则，会导致正常语音与无语音浏览器选择不同内容并产生维护分叉。

**Decision**：复用现有朗读触发和内容资格规则，只把最终输出从音频改为字幕显示。

**Consequences**：两种能力下行为一致，并继承当前隐私与 DOM 边界；内部输出协调器需在 audio-backed 与 text-only 之间选择，而不是复制文本抽取逻辑。

### 纯文字单次时长

**Context**：固定时长无法适配长短文本，永久保留又会造成持续遮挡和状态歧义。

**Decision**：按文本长度和语速估算 `3–15s`，结束后再以“已结束”保留约 `3s`；新目标立即替换并重置计时。

**Consequences**：纯文字单次模式拥有可预测的阅读窗口；计时算法应与连续模式共用，并由 token 防止旧计时器干扰新内容。

### 语音启动失败回退

**Context**：语音适配器可能同步抛错、在开始前回调错误或拒绝创建请求。直接清空字幕会丢失仍然可用的文字内容，连续会话也会被单段故障中断。

**Decision**：保留一次公共 `error`，但自动转为纯文字显示；连续会话按展示计时完成当前段并继续，后续段重新尝试正常语音。

**Consequences**：语音故障不会剥夺文字辅助能力；输出协调器必须区分“从未开始的音频失败”和有效播放后的错误，且禁止伪造语音事件。

### 音频中途错误

**Context**：音频开始后仍可能中断；立即清空或终止连续模式会让用户同时失去音频和文字上下文。

**Decision**：保留正文并转为纯文字“显示中”，以估算剩余时间完成当前段；连续模式随后继续。公共契约只有一次 `error`，没有伪造的 `speechend`。

**Consequences**：字幕为音频故障提供平滑降级；实现需记录请求开始时间，并使剩余时长计算、暂停和旧 token 失效可测试。

### 关闭字幕与输出会话

**Context**：正常音频不应因关闭视觉字幕而中断；但纯文字连续模式若失去唯一输出后继续推进，会形成不可见后台会话。

**Decision**：音频支持时只关闭字幕，不停止音频；完全无音频的纯文字连续模式则同步停止，纯文字单次显示直接清理。

**Consequences**：字幕保持视觉辅助的独立性，同时避免无输出会话；实现需要明确区分 audio-backed、segment-fallback 和 text-only-session。

### 朗读开关与字幕独立性

**Context**：大字幕需要在无语音能力下独立工作，因此不能继续把 `readingEnabled` 作为所有文本处理的唯一门禁。

**Decision**：朗读开关只决定是否尝试音频；字幕开关决定是否显示文字。连续会话在至少一种输出启用时保持，音频开关变化从当前／下一段按上述规则平滑切换。

**Consequences**：需要把“内容提取启用”从 `readingEnabled` 拆为 `readingEnabled || captionEnabled`，同时保持无输出时立即清理和既有隐私过滤。

### 无音频工具提示

**Context**：朗读关闭时完全丢弃工具提示会让字幕模式在页面内容与工具操作之间表现不一致。

**Decision**：工具操作提示继续走统一输出协调器，在没有音频时作为纯文字字幕显示。

**Consequences**：用户操作反馈与字幕能力保持一致；必须阻止“调整字幕设置 → 产生提示 → 再触发设置”的递归，并保持现有简短 live status 可用。

### 字幕设置反馈

**Context**：若位置或字号调整也进入字幕正文，会覆盖用户正在阅读的内容并可能形成反馈递归。

**Decision**：字幕自身设置只使用控件状态和简短 status 反馈，不进入正文输出通道。

**Consequences**：设置结果可感知而正文不中断；测试需断言文本 token、保留计时和滚动位置不因设置反馈被替换。

## Acceptance Criteria

- [ ] 单次和连续朗读均显示当前有效文本。
- [ ] end、cancel、error、close、destroy 后字幕按规则隐藏或清空。
- [ ] 旧请求回调不能覆盖新字幕。
- [ ] 长文本可读、可滚动且不遮挡关键控制。
- [ ] 键盘可打开、关闭、切换简体／繁体、开关拼音、调整字号并操作滚动区域。
- [ ] 简繁与拼音只改变视觉字幕，不改变实际朗读原文、事件 payload 或持久化正文。
- [ ] 发布产物把 `opencc-js` 与 `pinyin-pro` 内联在单个 `accessibility-tool.min.js` 中，示例网站和第三方网站无需引用任何附加语言资源。
- [ ] 简繁与拼音功能在断网状态下可用，运行时不发起 CDN、字典或语言包请求。
- [ ] 简体、繁体与拼音始终从同一原文快照独立生成；连续切换不会因反复转换损失文字。
- [ ] 屏幕阅读器不会因字幕文本产生第二次完整播报。
- [ ] 强制配色、深色和既有五种配色下均可辨认。

## Definition of Done

- 生命周期、视觉、键盘、读屏和长文本均有自动化与人工覆盖。

- 生产构建仍交付单个主 JS，并记录 minified 与 gzip 体积；若超出约 `2.8 MB`／`750 KB` 预算，需在验收记录中解释差异。
