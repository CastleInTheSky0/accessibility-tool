# 统一盲道区域与页面节点焦点朗读

## Goal

修正当前“完整盲道区域提示只在快捷键导航时朗读”的行为：开启朗读后，盲道区域通过快捷键、Tab、Shift+Tab 或程序聚焦进入时都使用同一份完整提示；区域内部节点则根据元素语义、状态和可访问名称生成稳定的中文朗读内容。

## What I already know

- 当前 `RegionNavigationController.navigate()` 会朗读完整区域提示，但普通 `focusin` 只切换区域高亮，不朗读该提示。
- 当前 `ReadingController` 在焦点进入后直接朗读 `getAccessibleText()`，只有名称与状态，没有“链接、图片、按钮”等语义前缀。
- 当前区域控制器和普通朗读控制器都会监听 `focusin`；区域容器聚焦时必须避免两次朗读以及后一条普通内容覆盖完整区域提示。
- 区域完整提示沿用已经确认的格式：`提示：您已进入{区域名称}{区域分类}，按下 Tab 键浏览信息；第 N 个，共 M 个`。
- 用户明确要求新窗口链接使用“打开新窗口链接 + 标题/名称”，图片使用“图片 + title 或 alt 内容”，按钮使用“按钮 + 名称/文本”，复选框、单选框和下拉框使用对应语义；其它标签统一使用 `文本：{内容}`。
- `public/index.html` 和两个 logo 仍是用户已有工作区改动，本任务不得覆盖或纳入。

## Assumptions

- “选中时”包含工具栏区域分类按钮触发的定位，以及任何让区域容器本身获得焦点的路径。
- 焦点进入区域内部链接、按钮等后，只朗读当前元素的语义内容，不重复区域进入提示；外层区域高亮继续保留。
- 朗读仍受现有“朗读”开关控制，不新增独立开关。

## Requirements

- 盲道区域容器通过快捷键、Tab、Shift+Tab 或程序聚焦获得焦点时，朗读同一条完整区域提示。
- 在同一个区域内从子节点返回区域容器时，也重新朗读完整区域提示。
- 区域容器的一次聚焦只能产生一条完整提示，不得随后被区域全部文本覆盖。
- 新窗口链接朗读为 `打开新窗口链接，{名称}`；普通链接及 `<area href>` 朗读为 `链接，{名称}`。
- 图片朗读为 `图片，{图片描述}`，图片描述来自确认后的 `title` / `alt` 优先级。
- 元素名称取值优先级固定为：`data-a11y-label` / `aria-readlabel` / `aria-label` → `aria-labelledby` → `title` → 适用的 `alt`（图片、area、图片按钮）→ 表单标签和值/当前选项 → 仅位于当前元素内部的文本选区 → 元素可见文本。
- 只有链接、图片、按钮、复选框、单选框和下拉框使用各自语义前缀；其它标签统一朗读为 `文本：{内容}`，内容按已确认优先级解析。
- 按钮使用 `按钮，{名称/文本}，{状态}`，同时覆盖原生 `<button>`、按钮类型 input 和等价 `role="button"`。
- 复选框和单选框分别使用 `复选框，{名称}，{状态}`、`单选框，{名称}，{状态}`；下拉框使用 `下拉框，{名称/当前选项}`，无显式名称的 ARIA combobox/listbox 可从 `aria-activedescendant` 或已选 option 解析当前选项。
- 保留已选中、未选中、已按下、已展开、已收起、不可用、当前项等现有状态信息。
- 保持 open Shadow Root、同源 iframe、忽略选择器和敏感字段保护行为。

- [x] 区域容器每次聚焦只调用一次语音，不朗读整块区域正文。
- [x] `target="_blank"` 链接、普通链接、图片、按钮、复选框、单选框和下拉框均按特殊语义规则朗读。
- [x] 标题、段落、普通容器、文本输入等其它标签统一朗读为 `文本：{内容}`。
- [x] 名称来源优先级、空名称回退和状态拼接有单元测试。

- 补充 DOM 朗读文本和区域 Tab 聚焦单元测试；按风险补充 E2E 验证。

## Technical Notes

- 主要文件：`src/features/region-navigation.ts`、`src/features/reading.ts`、`src/core/dom.ts`。
- 相关测试：`tests/unit/region-navigation.test.ts`、`tests/unit/dom.test.ts`，可能增加 ReadingController 聚焦协同测试。
- 普通焦点朗读必须能识别当前节点是否为已扫描区域容器，不能仅依赖监听器注册顺序。

## Decision (ADR-lite)

**Context**：同一元素可能同时提供工具专用名称、ARIA 名称、`title`、图片替代文本和可见内容，若没有固定优先级，不同焦点路径会得到不同朗读结果。

**Decision**：采用用户确认的统一优先级：工具专用/ARIA 显式名称优先，其次 `aria-labelledby`、`title`，适用元素再回退 `alt`，表单回退标签和值或当前选项，当前元素内部选区优先于最后的可见文本回退。链接、图片、按钮、复选框、单选框和下拉框使用各自语义格式，其它标签统一使用 `文本：{内容}`；现有状态继续追加，`aria-current="false"` 不视为当前项。

**Consequences**：接入方可通过显式属性稳定控制朗读；已有只依赖可见文本的页面仍可回退工作。`title` 与 `alt` 同时存在时按 `title` 朗读，同时避免为普通内容添加冗余类型词。

## Technical Approach

- 将“名称解析”和“类型语义拼接”分层，按钮纳入特殊类型，其它标签使用统一的 `文本：` 前缀。
- 区域控制器统一生成完整区域提示，并在普通 Tab/Shift+Tab 聚焦区域容器时触发；程序导航期间显式抑制焦点监听产生的重复提示。
- 普通朗读控制器通过区域控制器提供的区域容器判断跳过区域焦点，避免完整区域提示被随后触发的整块文本朗读覆盖。
- 为原生标签和对应常见 ARIA 角色提供相同的链接、图片、按钮、复选框、单选框、下拉框语义。
