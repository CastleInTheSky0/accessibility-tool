# 调整十字线颜色与功能状态图标

## Goal

提升无障碍工具栏的状态辨识度：页面十字线使用醒目的红色；具有开/关状态的功能在状态变化时同步切换为语义匹配的 SVG 图标，让用户不依赖按钮背景或朗读也能快速判断当前状态。

## What I already know

- 当前十字线覆盖层使用半透明橙色 `rgb(255 122 0 / 72%)`，与工具栏主强调色相同，用户要求改为红色。
- 工具栏已经通过 `aria-pressed` 和橙色背景表达选中状态，但所有控制始终使用创建时写入的同一个 SVG。
- 二态主功能包括朗读、大鼠标、十字线、大界面、固定、读屏专用；读屏专用工具栏中的“声音开关”复用 `readingEnabled` 状态。
- 语速、配色、放大、缩小、重置、帮助和退出属于数值/循环/瞬时操作，不是普通二态开关。
- 用户此前提供的参考图中，关闭的朗读图标是“扬声器 + X”，开启声音使用“扬声器 + 声波”；选中按钮继续使用橙色背景。
- 当前 SVG 使用 `currentColor`、统一 `24×24 viewBox` 和圆角描边，状态图标应继续遵循同一视觉语言。

## Visual Thesis

深色工具栏上的高对比功能标识：橙色只负责选中状态，红色只负责页面十字线；图标以简洁线性 SVG 直接表达开/关含义，不增加装饰性颜色和冗余徽标。

## Content Plan

- 保持现有“图标—名称—状态元信息”三层按钮结构和固定功能顺序。
- 状态变化只替换图标图形及已有的 ARIA 状态，不改变按钮名称和尺寸。
- 读屏专用工具栏沿用相同的声音开关图标规则。

## Interaction Thesis

- 状态提交后立即切换 SVG，不等待动画或语音完成。
- 图标切换保持按钮盒尺寸稳定，不产生工具栏抖动。
- 不增加装饰性动画；继续尊重现有 `prefers-reduced-motion` 约束。

## Confirmed Decisions

- 每个真正的二态功能使用专属的开/关图标，而不是统一叠加一个勾选徽标。
- 首版覆盖非二态状态中的配色和语速图标；放大和缩小保留固定操作图标，当前比例仍由既有状态文字表达。
- 配色和语速图标采用“保留操作含义 + 同步反映当前状态”的组合方案：配色图标展示当前实际色板，语速图标通过仪表指针反映当前速率。
- 放大/缩小图标不显示进度、比例或刻度，只保留固定且清晰的放大镜 `+`/`-` 操作含义；当前缩放比例继续由按钮现有状态文字和可访问信息表达。
- 橙色 `aria-pressed="true"` 背景继续保留，图标变化作为第二种非颜色状态提示。
- 十字线颜色使用现有可主题化危险色变量 `--a11y-danger`，默认值为红色；同时保留对明暗背景可见的轮廓。

## Requirements

- 页面横向、纵向十字线统一使用红色，并保持不拦截鼠标、滚动和焦点。
- 朗读关闭时显示“扬声器 + X”，开启时显示“扬声器 + 声波”。
- 大鼠标、十字线、大界面、固定、读屏专用分别提供语义明确的关闭/开启 SVG；声音开关与朗读使用同一声音状态规则。
- 配色图标反映五种实际配色；语速图标反映当前速率；放大/缩小图标固定显示放大镜加号/减号，不在图标中呈现当前缩放级别。
- 状态图标必须与真实 `AccessibilityToolState` 和 `aria-pressed` 同步，自动恢复、重置、退出全屏等外部状态变化也要正确更新。
- SVG 继续使用 `currentColor`，不使用外部图标字体、图片或运行时依赖。
- 不改变工具栏现有顺序、尺寸、标签、键盘模型和 Shadow DOM 隔离。
- 不修改或覆盖 `public/index.html` 与两个未跟踪 Logo 的用户内容。

## Acceptance Criteria

- [ ] 十字线开启后横线和竖线均为红色，并在浅色、深色页面上保持清晰。
- [ ] 朗读按钮和“声音开关”在关闭/开启间切换 X/声波图标。
- [ ] 纳入首版范围的其它二态功能在 `aria-pressed` 改变时同步切换到语义匹配图标。
- [ ] 配色图标可区分五种实际配色，语速仪表指针随当前速率变化；放大/缩小固定使用清晰的放大镜加号/减号，且不出现进度、比例或刻度。
- [ ] 重置、自动恢复和浏览器退出全屏后图标与最终状态一致。
- [ ] 图标切换不改变按钮或工具栏尺寸，不影响焦点样式与键盘操作。
- [ ] 单元测试、Chrome/Edge E2E、类型检查、Lint 和构建通过。

## Definition of Done

- 状态图标映射、ToolbarUI 更新逻辑、SCSS、测试和运行契约同步。
- 所有 SVG 保持 `aria-hidden="true"`，按钮可访问名称继续由控件提供。
- 不引入新依赖或外部资源。

## Technical Approach

- 在 `src/ui/toolbar.ts` 中集中维护无状态图标与状态化图标渲染器，输入 `AccessibilityToolState` 和控制 ID，输出统一的内联 SVG 字符串。
- `ToolbarUI.updateState()` 在同步文本元信息和 `aria-pressed` 的同一次更新中替换 `.a11y-control__icon` 内容，并写入稳定的 `data-icon-state` 供调试与测试断言。
- 二态图标只从最终真实状态派生；全屏图标以浏览器 Fullscreen API 的最终结果为准，重置和偏好恢复也复用同一状态更新入口。
- 所有 SVG 保持 `24×24`、`currentColor`、圆角线性描边和 `aria-hidden="true"`，图标变化不参与按钮可访问名称。
- 十字线使用 `--a11y-danger` 作为线条主色，并以现有高对比轮廓策略保证浅色、深色背景均可见。

## Decision (ADR-lite)

**Context**：单靠橙色选中背景无法让所有用户快速区分开关状态；配色和语速适合在图标中表达当前配置，但缩放进度会使放大/缩小图标显得拥挤。

**Decision**：二态功能采用各自专属的开/关图形；配色和语速采用同时表达操作与当前值的状态化 SVG；放大/缩小只保留固定的放大镜加号/减号，缩放比例沿用现有状态文字；状态图标全部由现有工具状态派生，不新增独立 UI 状态。

**Consequences**：状态辨识度和非颜色提示得到提升，工具栏结构与键盘模型保持不变；图标映射和测试用例会增加，但不引入依赖，也不会产生额外持久化数据。

## Out of Scope (explicit)

- 不重画整个工具栏或改变分组与功能顺序。
- 不修改移动端布局。
- 不改变功能业务逻辑、状态持久化或快捷键。
- 不新增用户上传或接入方自定义 SVG 的 API。
