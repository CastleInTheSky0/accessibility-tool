# 记录云端语音接入后续开发方案

## Goal

把当前已讨论并确认的云端语音接入思路整理为仓库内可持续维护的后续开发方案，供未来立项、评审和实现时继续补充，不改变当前 v0.1.0 的运行行为。

## Requirements

- 在 `docs/` 下新增一份独立的云端语音接入方案文档，并在 README 的文档索引中提供入口。
- 明确该文档是后续开发提案，不代表当前版本已经支持云端 TTS。
- 记录推荐架构：无障碍工具通过远程语音适配器调用自有 TTS 网关，由网关封装云厂商并返回音频给前端播放。
- 记录首选策略：短焦点提示继续使用浏览器语音，较长正文按配置使用云端语音；云端超时或失败时自动回退浏览器语音。
- 结合现有 `SpeechAdapter`、`SpeechController` 和 `BrowserSpeechAdapter` 说明前端可复用的扩展点。
- 记录后端网关的职责、接口草案、租户鉴权、限流与额度、缓存、日志与隐私、请求取消及过期响应处理。
- 记录首版建议先接入腾讯云精品音色，并保留供应商适配层；首版不做多厂商自动容灾切换。
- 提供带日期的成本快照和官方参考链接，并提醒实施前复核最新价格与计费口径。
- 给出分阶段实施顺序、验收关注点以及明确的非本次范围。
- 文档结构应便于后续在同一文件中追加决策、变更记录和实施结果。

## Technical Approach

新增 `docs/cloud-tts-future-plan.md` 作为 living document。文档以混合朗读策略为默认建议：高频、短文本、低延迟的交互提示使用浏览器 `speechSynthesis`；较长正文在接入方启用后通过 `RemoteSpeechAdapter` 请求自有 TTS 网关。网关持有云厂商密钥，负责供应商协议转换、缓存、租户治理、成本统计和安全控制。远程请求失败、超时或不可用时，由前端回退到 `BrowserSpeechAdapter`。

## Decision (ADR-lite)

**Context**：前端直接调用云厂商会暴露密钥，并把厂商协议、成本治理、缓存与合规逻辑耦合到工具包；所有朗读都走云端又会增加键盘焦点提示的延迟和页面文本外发范围。

**Decision**：采用“自有后端 TTS 网关 + 前端混合朗读 + 本地降级”的架构。首个供应商建议腾讯云精品音色，后端保留供应商适配接口，但首版只接一个厂商。

**Consequences**：需要维护一项轻量后端服务，但密钥、成本、缓存、配额和供应商替换都可集中治理；前端仍需处理请求取消、音频生命周期和失败降级。

## Out of Scope

- 本任务不实现 `RemoteSpeechAdapter`、后端网关、数据库、缓存服务或部署脚本。
- 不改变当前浏览器语音的默认行为。
- 不实现多厂商自动切换、音色管理后台、计费结算系统或移动端专项能力。
- 不承诺文档中的接口字段为最终稳定 API；实际开发立项后可继续调整并记录变更。
