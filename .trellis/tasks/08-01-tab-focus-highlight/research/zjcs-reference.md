# 常山县政府阅读辅助交互调研

调研页面：<https://www.zjcs.gov.cn/>

调研日期：2026-08-01

## 调研边界

- 仅记录可通过浏览器操作和运行时 DOM / 计算样式观察到的行为。
- 不复制、改写或依赖第三方压缩源码；本项目只独立实现等价交互。
- 本次只影响当前任务中的焦点提示、盲道区域提示、区域循环与生命周期清理。

## 实测行为

1. 打开“阅读辅助”后，页面 `body` 顶部预留约 `100px`，工具栏固定在视口顶部。
2. `Ctrl+Alt+R` 进入读屏专用界面后，左侧显示六类盲道区域及实时数量：
   - 视窗区：`Alt+1`
   - 导航区：`Alt+2`
   - 交互区：`Alt+3`
   - 服务区：`Alt+4`
   - 列表区：`Alt+5`
   - 正文区：`Alt+6`
3. 连续按 `Alt+2` 会按照页面 DOM 顺序在两个导航区之间循环：顶部导航区 -> 底部导航区 -> 顶部导航区。
4. 定位区域时：
   - 区域滚动进入视口并成为 `document.activeElement`；
   - 非原生可聚焦区域临时获得 `tabindex="0"`；
   - 区域获得 `aria-regionactive="true"` 以及活动状态类；
   - 区域本身获得焦点时只显示黄色焦点框。
5. 从区域容器按 `Tab` 后，浏览器按原生 DOM 顺序进入第一个内部可聚焦节点：
   - 外层区域保留深橙色框；
   - 当前内部节点显示黄色框；
   - 内部节点不被补写 `tabindex`。
6. 从第一个内部节点按 `Shift+Tab` 会回到区域容器；再次按 `Shift+Tab` 离开区域后，区域活动框清除，焦点继续遵循页面原生顺序。
7. 切换到另一个同类区域时，旧区域的活动属性和活动视觉立即清除，新区域成为唯一活动区域。
8. 页面原有蓝色 `:focus` 轮廓不会与产品提示框叠加；产品直接接管当前真实节点的 `outline` 表现。

## 实测视觉

第三方产品在真实页面节点上使用如下两种状态：

```css
.ariafocus {
  outline: 2px solid rgba(255, 184, 0, 1) !important;
  transition: outline 250ms;
}

.ariaregion,
[aria-regionactive="true"] {
  outline: 2px solid #ff6c00;
  transition: outline 250ms;
}
```

- 当前焦点：黄色 `#ffb800`。
- 活动盲道区域：深橙色 `#ff6c00`。
- 当区域容器自身有焦点时，黄色焦点表现覆盖区域色。
- 当焦点进入子节点时，区域恢复深橙色，子节点显示黄色。

## 对本项目的实现结论

- 工具栏仍保留在 Shadow Root 中，继续与宿主样式隔离。
- 朗读目标继续使用独立覆盖层，不与焦点或区域状态共用生命周期。
- 页面焦点与活动盲道区域改为直接作用于真实节点的可逆内联 `outline`，并使用 `!important` 抵抗宿主 CSS。
- 使用独立 `DomLedger` 保存并恢复原始内联样式、属性及优先级；切换区域、关闭和销毁时不得留下状态。
- 区域容器临时使用 `tabindex="0"`，但绝不修改后代节点的 `tabindex`、不拦截 Tab、不制造自定义遍历顺序。
- 直接作用于节点后，不再需要针对焦点框和区域框计算固定定位覆盖层坐标；开放 Shadow Root 和同源 iframe 中的目标也能自然跟随自身布局。

## 接入方补充决定

2026-08-01，接入方进一步明确：普通 Tab 也必须先停在已经识别的盲道区域容器，再进入区域内部内容，不能要求用户先通过分类按钮或快捷键激活区域。工具因此需要在打开期间自动为所有原本不可聚焦的可见区域容器补 `tabindex="0"`，并在区域失效或工具关闭时恢复原值。
